Approach this UI work with high craft—never settle for generic "looks done" output:

1. **Define a clear point of view:** Align with the product's explicit visual language, hierarchy, and brand feel (ask if unclear) instead of defaulting to generic template UI.
2. **Encode standards into the system:** Put spacing, typography, tokens, states, and patterns into reusable primitives and variants rather than one-off inline hacks.
3. **Refuse to confuse done with good:** Critically review your own output from a real user's perspective—empty, loading, and error states, alignment, contrast, responsiveness, micro-interactions, and friction—and refine before presenting.
4. **Elevate, don't just ship:** Ground decisions in real references/constraints from the codebase and aim for intentional, cohesive artistry that solves the user problem cleanly.
